Pure Bash REST API Framework
ShellRest es un framework HTTP escrito completamente en Bash 5+. Sin dependencias de runtime — solo bash, sqlite3, jq y nc. Router con path params, ORM-like helpers, sistema de migraciones, middleware pipeline.
v1.0.0 Bash 5+ SQLite 3+ MIT License

Overview

ShellRest convierte un script Bash en un servidor HTTP funcional. Cada request dispara un proceso hijo que sourcéa el framework, matchea la ruta, ejecuta el handler y devuelve una respuesta HTTP/1.1 completa.

Stack mínimo requerido:

bash
bash --version | head -1 GNU bash, version 5.3.9(1)-release sqlite3 --version 3.52.0 2025-01-09 jq --version jq-1.7.1 nc -h 2>&1 | head -1 OpenBSD netcat

Flujo de una request:

nc (acepta TCP) → api.sh (fork) → middleware pipeline → route_request() → handler() → http_response()
INFOCada request es un proceso Bash independiente. No hay estado compartido entre requests — todo estado persiste en SQLite.

Quick Start

Clonar e inicializar

bash 
git clone https://github.com/tu-usuario/shellrest.git
cd shellrest

# Crear base de datos y ejecutar migraciones
./migrate.sh

# Arrancar el servidor (puerto 8082 por defecto)
./server.sh

Primera request

bash 
# GET /users
curl http://localhost:8082/users

# POST /users
curl -X POST http://localhost:8082/users \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","email":"alice@example.com"}'

# GET /users/1
curl http://localhost:8082/users/1

# DELETE /users/1
curl -X DELETE http://localhost:8082/users/1

Crear una ruta nueva en 60 segundos

routes/health.sh 
#!/bin/bash

register_route "GET" "/health" "get_health"

get_health() {
    http_response "200 OK" "application/json" \
        '{"status":"ok","version":"1.0.0"}'
}
TIPShellRest carga automáticamente todos los *.sh dentro de routes/. No necesitas registrar el archivo.

Configuration

ShellRest lee configuración desde .env en la raíz del proyecto. Todas las variables son opcionales — si no existen, se usan los defaults.

.env 
API_PORT=8082
API_HOST=localhost
DB_FILE=/ruta/absoluta/database.db
LOG_FILE=/var/log/shellrest/access.log
DEBUG=false
Variable Default Descripción
API_PORT 8082 Puerto TCP donde escucha el servidor
API_HOST localhost Host del servidor
DB_FILE sqlite_data.db Ruta al archivo SQLite. Relativa a la raíz del proyecto
LOG_FILE access.log Ruta al log de acceso escrito por logging_middleware
DEBUG false Habilita debug_log() — escribe a stderr
CORS_ORIGIN * Valor del header Access-Control-Allow-Origin
CORS_METHODS GET, POST, PUT, DELETE, OPTIONS Métodos HTTP permitidos por CORS
CORS_HEADERS Content-Type, Authorization Headers permitidos por CORS

API de configuración

load_config () → void
Carga el archivo .env y exporta todas las variables con sus defaults. Se llama automáticamente en api.sh y server.sh.
get_config (key: string) → string
Retorna el valor de una clave de configuración por nombre.
ParamTipoValores válidos
keystringport · host · db_file · log_file · debug
ejemplo
PORT=$(get_config "port")    # "8082"
DB=$(get_config "db_file")   # "/ruta/a/sqlite_data.db"
debug_log (...args) → void
Escribe a stderr solo cuando DEBUG=true. No tiene efecto en producción.
ejemplo
debug_log "procesando user_id=$user_id"
# [DEBUG] procesando user_id=42  (solo si DEBUG=true)

Routing

El router usa arrays asociativos de Bash para mapear METHOD PATH → función handler. Soporta rutas exactas y rutas con path parameters ({param}).

register_route

register_route (method, pattern, handler)
Registra una ruta asociando un método HTTP y un patrón de path con una función Bash.
ParamTipoDescripción
methodstringGET · POST · PUT · PATCH · DELETE
patternstringPath con soporte para {param} y wildcard *
handlerstringNombre de la función Bash que maneja la request
routes/users.sh
register_route "GET"    "/users"            "get_users"
register_route "POST"   "/users"            "post_users"
register_route "GET"    "/users/{id}"       "get_user"
register_route "PUT"    "/users/{id}"       "put_user"
register_route "DELETE" "/users/{id}"       "delete_user"
register_route "GET"    "/users/{id}/posts" "get_user_posts"

Path Parameters

Los segmentos entre llaves {nombre} en el patrón se extraen automáticamente y se pasan al handler como argumentos posicionales en el orden en que aparecen en el path.

path params
register_route "GET" "/users/{id}" "get_user"

get_user() {
    local id="$1"          # PATH_PARAMS["id"]
    # ...
}

# Múltiples params
register_route "GET" "/users/{user_id}/orders/{order_id}" "get_user_order"

get_user_order() {
    local user_id="$1"     # primer param
    local order_id="$2"    # segundo param
    # ...
}
INFOEl array global PATH_PARAMS también está disponible: ${PATH_PARAMS["id"]}. Los args posicionales son más convenientes para la mayoría de los casos.

Query String

Los query params se parsean con parse_query_string y se exportan como variables con prefijo QUERY_.

query string
# Request: GET /users?page=2&limit=10

# api.sh ya parsea el query string automáticamente
# En tu handler:

get_users() {
    local page="${QUERY_page:-1}"
    local limit="${QUERY_limit:-20}"

    local result
    result=$(execute_query \
        "SELECT * FROM users LIMIT $limit OFFSET $(( (page-1) * limit ));" json)
    http_response "200 OK" "application/json" "$result"
}

Headers

get_header (header_name: string) → string
Busca un header HTTP por nombre (case-insensitive) en la request actual. Retorna vacío si no existe.
ejemplo
token=$(get_header "Authorization")
# "Bearer eyJhbGciOiJIUzI1NiJ9..."

content_type=$(get_header "Content-Type")
# "application/json"

load_routes

load_routes (dir?: string = "routes") → void
Sourcéa todos los *.sh dentro del directorio especificado. Se llama automáticamente en api.sh. Cada archivo puede registrar las rutas que quiera.

HTTP Responses

http_response (status, content_type, body)
Escribe una respuesta HTTP/1.1 completa a stdout, incluyendo headers CORS automáticos y Content-Length calculado.
ParamTipoEjemplos
statusstring"200 OK" · "201 Created" · "400 Bad Request" · "404 Not Found" · "500 Internal Server Error"
content_typestring"application/json" · "text/plain" · "text/html"
bodystringCuerpo de la respuesta
ejemplos
# 200 con JSON
http_response "200 OK" "application/json" '{"id":1,"name":"Alice"}'

# 201 Created
http_response "201 Created" "application/json" "$new_resource"

# 204 No Content (body vacío)
http_response "204 No Content" "application/json" ""

# 400 Bad Request
http_response "400 Bad Request" "application/json" \
    "$(json_error "username is required")"

# 404 Not Found
http_response "404 Not Found" "application/json" \
    "$(json_error "User not found")"

# 401 Unauthorized
http_response "401 Unauthorized" "application/json" \
    "$(json_error "Authentication required")"

# 500 Internal Server Error
http_response "500 Internal Server Error" "application/json" \
    "$(json_error "Unexpected error")"

Helpers de respuesta

json_error (message: string) → string
Retorna un JSON de error estándar: {"error":"message"}
ejemplo
json_error "User not found"
# {"error":"User not found"}
json_success (message: string) → string
Retorna un JSON de éxito estándar: {"message":"..."}
ejemplo

Todos los headers CORS se inyectan automáticamente en cada llamada a http_response. Se controlan desde .env:

CORS_METHODS=GET, POST, PUT, DELETE
CORS_HEADERS=Content-Type, Authorization, X-Api-Key

Database

ShellRest usa SQLite vía CLI (sqlite3). El módulo utils.sh provee helpers de alto nivel sobre execute_query. Todo retorna JSON por defecto.

Queries básicos

db_select (table, fields?, where?, format?)
Ejecuta un SELECT y retorna el resultado. Formato JSON por defecto.
ParamDefaultDescripción
table—Nombre de la tabla
fields*Columnas a seleccionar
where""Cláusula WHERE (sin la palabra WHERE)
formatjsonjson · csv · table
ejemplo
# SELECT * FROM users
db_select "users"

# SELECT id, username, email FROM users
db_select "users" "id, username, email"

# SELECT id, username FROM users WHERE id = 5
db_select "users" "id, username" "id = 5"

# SELECT * FROM users WHERE is_active = 1 (en CSV)
db_select "users" "*" "is_active = 1" "csv"
db_insert (table, fields, values)
Ejecuta un INSERT. Usar safe_sql_string() para escapar valores de texto.
ejemplo
db_insert "users" "username, email" \
    "$(safe_sql_string "$username"), $(safe_sql_string "$email")"

# Obtener el ID del insert
id=$(db_get_last_insert_id)
db_update (table, set_clause, where_clause)
Ejecuta un UPDATE. Verificar db_get_changes() para saber si afectó filas.
ejemplo
db_update "users" \
    "username = $(safe_sql_string "$username"), email = $(safe_sql_string "$email")" \
    "id = $id"

changes=$(db_get_changes)
if [ "${changes:-0}" -gt 0 ]; then
    http_response "200 OK" "application/json" "$(db_select "users" "*" "id=$id")"
else
    http_response "404 Not Found" "application/json" "$(json_error "Not found")"
fi
db_delete (table, where_clause)
Ejecuta un DELETE. Verificar db_get_changes() para confirmar que algo fue eliminado.
ejemplo
db_delete "users" "id = $id"

changes=$(db_get_changes)
[ "${changes:-0}" -gt 0 ] \
    && http_response "204 No Content" "application/json" "" \
    || http_response "404 Not Found" "application/json" "$(json_error "Not found")"

Conteo y existencia

db_count (table, where?) → number
Retorna el número de filas que cumplen la condición.
ejemplo
total=$(db_count "users")                    # total de users
activos=$(db_count "users" "is_active = 1")  # solo activos
db_exists (table, where) → bool
Retorna 0 (true) si existe al menos una fila que cumpla la condición, 1 (false) si no.
ejemplo
if db_exists "users" "email = $(safe_sql_string "$email")"; then
    http_response "409 Conflict" "application/json" \
        "$(json_error "Email already registered")"
    return
fi

JOINs

db_inner_join (select, table1, table2, on, where?, order?, format?)
INNER JOIN entre dos tablas.
ejemplo
result=$(db_inner_join \
    "o.id, u.username, p.name AS product, o.quantity" \
    "orders o" \
    "users u" \
    "u.id = o.user_id" \
    "o.id = $id" \
    "o.id DESC"
)
db_left_join (select, table1, table2, on, where?, order?, format?)
LEFT JOIN entre dos tablas. Incluye filas de table1 sin match en table2.
ejemplo
result=$(db_left_join \
    "u.id, u.username, COUNT(o.id) AS order_count" \
    "users u" \
    "orders o" \
    "o.user_id = u.id"
)
db_multi_join (select, from, joins, where?, group_by?, having?, order?, limit?, format?)
JOIN múltiple con soporte completo para GROUP BY, HAVING, ORDER BY y LIMIT.
ejemplo
result=$(db_multi_join \
    "o.id, u.username, p.name, o.quantity, o.order_date" \
    "orders o" \
    "JOIN users u ON u.id = o.user_id JOIN products p ON p.id = o.product_id" \
    "o.order_date > '2025-01-01'" \
    "" \
    "" \
    "o.order_date DESC" \
    "50"
)
db_aggregate (select, from, where?, group_by?, having?, format?)
Queries de agregación — SUM, COUNT, AVG, MIN, MAX con GROUP BY y HAVING.
ejemplo
# Total vendido por producto
result=$(db_aggregate \
    "product_id, SUM(quantity) AS total_sold" \
    "orders" \
    "" \
    "product_id" \
    "total_sold > 10"
)

Raw query

execute_query (query, format?) → string
Ejecuta SQL arbitrario contra la base de datos. Retorna el resultado en el formato especificado.
ejemplo
# Query complejo con subquery
result=$(execute_query "
    SELECT u.id, u.username,
           (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) AS order_count
    FROM users u
    WHERE u.is_active = 1
    ORDER BY order_count DESC
    LIMIT 10;
" json)

# DDL directo
execute_query "CREATE INDEX IF NOT EXISTS idx_users_email ON users(email);"

Utilidades de DB

safe_sql_string (value: string) → string
Escapa comillas simples y envuelve el valor en comillas SQL. Siempre usar para valores de texto en queries.
ejemplo
safe_sql_string "O'Brien"   # → 'O''Brien'
safe_sql_string "Alice"     # → 'Alice'

# En un INSERT:
db_insert "users" "username" "$(safe_sql_string "$username")"
WARNNunca interpolar variables directamente en queries sin safe_sql_string(). Los valores numéricos validados con validate_integer() son la única excepción segura.

Validation

Módulo de validación para inputs de usuario. Todas las funciones retornan 0 (success) o 1 (failure) para uso directo en condicionales.

validate_required_fields (json_body, ...fields) → bool
Verifica que todos los campos especificados existan y no sean nulos en el JSON recibido.
ejemplo
if ! validate_required_fields "$body" "username" "email" "password"; then
    http_response "400 Bad Request" "application/json" \
        "$(json_error "username, email and password are required")"
    return
fi
validate_email (email: string) → bool
Valida formato de email con regex. No verifica existencia del dominio.
ejemplo
email=$(get_json_field "$body" "email")
if [ -n "$email" ] && ! validate_email "$email"; then
    http_response "400 Bad Request" "application/json" \
        "$(json_error "invalid email format")"
    return
fi
validate_integer (value: string) → bool
Verifica que el valor sea un entero positivo ([0-9]+). Útil para IDs antes de usarlos en queries.
ejemplo
validate_integer "42"    # → 0 (true)
validate_integer "abc"   # → 1 (false)
validate_integer "3.14"  # → 1 (false)
validate_path_param (param: string) → bool
Valida que un path param sea entero. Si falla, escribe automáticamente un 400 y retorna 1. Patrón estándar en todos los handlers con {id}.
ejemplo
get_user() {
    local id="$1"
    validate_path_param "$id" || return   # auto-responde 400 si no es entero
    # ... seguro usar $id en query
}
validate_json (json: string) → bool
Verifica que el string sea JSON válido usando jq empty.
ejemplo
if ! validate_json "$body"; then
    http_response "400 Bad Request" "application/json" \
        "$(json_error "Invalid JSON")"
    return
fi
sanitize_input (input: string) → string
Elimina caracteres de control no imprimibles (\x00-\x1F y \x7F) del input.
ejemplo
clean_name=$(sanitize_input "$raw_name")

Middleware

El middleware pipeline se ejecuta antes de que la request llegue al route handler. Si un middleware retorna 1 (failure), el pipeline se detiene y no se llama al handler.

Request → logging_middleware → cors_middleware → auth_middleware (opt) → handler()
add_middleware (function_name: string)
Agrega una función al pipeline. El orden de llamada refleja el orden de registro.
api.sh
add_middleware "logging_middleware"
add_middleware "cors_middleware"
add_middleware "auth_middleware"    # opcional
add_middleware "rate_limit_middleware"  # custom

Middlewares built-in

logging_middleware

Escribe cada request a $LOG_FILE con timestamp, método y path.

access.log
[2025-09-15 22:05:01] GET /users
[2025-09-15 22:05:03] POST /users
[2025-09-15 22:05:07] GET /users/1
[2025-09-15 22:05:12] DELETE /users/1

cors_middleware

Intercepta requests OPTIONS (preflight) y responde 204 No Content con los headers CORS. Para el resto de métodos, retorna 0 y deja pasar.

auth_middleware

Ejemplo incluido: protege rutas bajo /protected/*. Verifica que el header Authorization esté presente; si no, responde 401.

middleware.sh — auth_middleware
auth_middleware() {
    local method="$1"
    local path="$2"
    local auth_header
    auth_header=$(get_header "Authorization")

    if [[ "$path" == "/protected"* ]] && [ -z "$auth_header" ]; then
        http_response "401 Unauthorized" "application/json" \
            "$(json_error "Authentication required")"
        return 1
    fi
    return 0
}

Middleware custom

Un middleware es cualquier función Bash que recibe (method, path, body) y retorna 0 para continuar o 1 para cortar el pipeline.

ejemplo — rate limiter simple
rate_limit_middleware() {
    local method="$1"
    local path="$2"
    local ip="${REMOTE_ADDR:-unknown}"
    local window=60
    local max_requests=100

    local count_file="/tmp/rl_${ip}"
    local now count
    now=$(date +%s)
    count=$(cat "$count_file" 2>/dev/null || echo "0 0")

    local last_reset count_val
    last_reset=$(echo "$count" | awk '{print $1}')
    count_val=$(echo "$count" | awk '{print $2}')

    if (( now - last_reset >= window )); then
        count_val=0
        last_reset=$now
    fi

    count_val=$(( count_val + 1 ))
    echo "$last_reset $count_val" > "$count_file"

    if (( count_val > max_requests )); then
        http_response "429 Too Many Requests" "application/json" \
            "$(json_error "Rate limit exceeded")"
        return 1
    fi
    return 0
}

# Registrar en api.sh:
add_middleware "rate_limit_middleware"

Migrations

El sistema de migraciones trackea qué scripts ya se ejecutaron en la tabla migrations de SQLite. Cada migración tiene funciones up() y down().

Comandos de migrate.sh

bash 
# Ejecutar todas las migraciones pendientes
./migrate.sh

# Ver estado de todas las migraciones
./migrate.sh status

# Rollback de la última migración
./migrate.sh rollback

# Rollback de una migración específica
./migrate.sh rollback 20250915_220501_users.sh

# Drop total + re-ejecutar todas (DESTRUCTIVO)
./migrate.sh fresh

# Rollback de TODAS las migraciones
./migrate.sh reset
./migrate.sh status
Migration Status: ================== ✓ 20250915_220501_users.sh (executed) ✓ 20250915_223331_products.sh (executed) ✓ 20250915_223649_orders.sh (executed) ✗ 20260427_151148_users.sh (pending)

Crear una migración

bash
# Crear tabla (template completo)
./make_migration.sh create_posts_table posts

# Agregar columna (template de add_column)
./make_migration.sh add_bio_to_users users

# Migración genérica
./make_migration.sh add_user_index

El script genera un archivo con timestamp en migrations/ listo para editar:

migrations/20260427_151148_create_posts_table.sh
#!/bin/bash

source "$(dirname "$0")/../shellrest/migration.sh"

up() {
    local columns="$(id_column),
    $(string_column "title" 255 false),
    $(string_column "body"),
    $(integer_column "user_id" false),
    $(boolean_column "published" "0"),
    $(timestamps_columns)"

    local constraints="$(foreign_key "user_id" "users")"

    create_table "posts" "$columns" "$constraints"

    create_index "idx_posts_user_id" "posts" "user_id"
    create_index "idx_posts_published" "posts" "published"
}

down() {
    drop_index "idx_posts_user_id"
    drop_index "idx_posts_published"
    drop_table "posts"
}

if [ "$1" = "up" ]; then
    up
elif [ "$1" = "down" ]; then
    down
else
    echo "Usage: $0 {up|down}"
    exit 1
fi

Schema Builder

Helpers que generan fragmentos de DDL SQL. Se usan dentro de las funciones up() de las migraciones.

Column types

FunciónSQL generadoFirma
id_column() id INTEGER PRIMARY KEY AUTOINCREMENT sin parámetros
string_column() name TEXT [NOT NULL] (name, length=255, nullable=true)
integer_column() name INTEGER [NOT NULL] (name, nullable=true)
decimal_column() name DECIMAL(10,2) [NOT NULL] (name, precision_scale="10,2", nullable=true)
boolean_column() name BOOLEAN [NOT NULL] [DEFAULT val] (name, default="", nullable=true)
datetime_column() name DATETIME [NOT NULL] [DEFAULT ...] (name, default="", nullable=true) — usa "now" para CURRENT_TIMESTAMP
timestamps_columns() created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP, updated_at... sin parámetros — agrega ambas

Constraints e Indexes

FunciónSQL generadoFirma
foreign_key() FOREIGN KEY (col) REFERENCES table(id) (column, ref_table, ref_column="id")
unique_constraint() UNIQUE (columns) (columns)
create_index() CREATE [UNIQUE] INDEX IF NOT EXISTS ... (name, table, columns, unique=false)
drop_index() DROP INDEX IF EXISTS name (name)
create_table() CREATE TABLE IF NOT EXISTS ... (name, columns, constraints="")
drop_table() DROP TABLE IF EXISTS name (name)
add_column() ALTER TABLE t ADD COLUMN ... (table, column_definition)
rename_table() ALTER TABLE old RENAME TO new (old_name, new_name)
schema builder — ejemplo completo
up() {
    local columns="$(id_column),
    $(string_column "title" 255 false),
    $(string_column "slug" 255 false),
    $(string_column "body"),
    $(integer_column "user_id" false),
    $(decimal_column "price" "8,2"),
    $(boolean_column "is_published" "0" false),
    $(datetime_column "published_at"),
    $(timestamps_columns)"

    local constraints="$(unique_constraint "slug"),
    $(foreign_key "user_id" "users")"

    create_table "posts" "$columns" "$constraints"

    create_index "idx_posts_slug"      "posts" "slug"        "true"
    create_index "idx_posts_user_id"   "posts" "user_id"
    create_index "idx_posts_published" "posts" "is_published"
}

JSON Utilities

get_json_field (body, field) → string
Extrae un campo del JSON del body. Retorna vacío si el campo no existe o es null.
ejemplo
# body = '{"username":"alice","age":30}'
username=$(get_json_field "$body" "username")  # "alice"
age=$(get_json_field "$body" "age")            # "30"
missing=$(get_json_field "$body" "email")      # "" (vacío)
get_required_field (body, field) → string | exit 1
Como get_json_field pero retorna 1 si el campo está vacío. Útil en combinación con ||.
ejemplo
username=$(get_required_field "$body" "username") || {
    http_response "400 Bad Request" "application/json" \
        "$(json_error "username is required")"
    return
}

routes/posts.sh
#!/bin/bash

register_route "GET"    "/posts"      "get_posts"
register_route "POST"   "/posts"      "post_posts"
register_route "GET"    "/posts/{id}" "get_post"
register_route "PUT"    "/posts/{id}" "put_post"
register_route "DELETE" "/posts/{id}" "delete_post"

get_posts() {
    local result
    result=$(db_inner_join \
        "p.id, p.title, u.username AS author, p.published, p.created_at" \
        "posts p" "users u" "u.id = p.user_id" \
        "" "p.created_at DESC")
    [ -z "$result" ] && result="[]"
    http_response "200 OK" "application/json" "$result"
}

get_post() {
    local id="$1"
    validate_path_param "$id" || return

    local result
    result=$(db_inner_join \
        "p.id, p.title, p.body, u.username AS author, p.published, p.created_at" \
        "posts p" "users u" "u.id = p.user_id" "p.id = $id")

    if [ -z "$result" ] || [ "$result" = "[]" ]; then
        http_response "404 Not Found" "application/json" "$(json_error "Post not found")"
    else
        http_response "200 OK" "application/json" "$result"
    fi
}

post_posts() {
    local body="$1"

    if ! validate_required_fields "$body" "title" "user_id"; then
        http_response "400 Bad Request" "application/json" \
            "$(json_error "title and user_id are required")"
        return
    fi

    local title body_text user_id published
    title=$(get_json_field "$body" "title")
    body_text=$(get_json_field "$body" "body")
    user_id=$(get_json_field "$body" "user_id")
    published=$(get_json_field "$body" "published")
    published="${published:-0}"

    if ! validate_integer "$user_id"; then
        http_response "400 Bad Request" "application/json" \
            "$(json_error "user_id must be an integer")"
        return
    fi

    if ! db_exists "users" "id = $user_id"; then
        http_response "404 Not Found" "application/json" \
            "$(json_error "User not found")"
        return
    fi

    db_insert "posts" "title, body, user_id, published" \
        "$(safe_sql_string "$title"), $(safe_sql_string "$body_text"), $user_id, $published"

    local id
    id=$(db_get_last_insert_id)
    http_response "201 Created" "application/json" \
        "$(db_select "posts" "id, title, body, user_id, published, created_at" "id = $id")"
}

put_post() {
    local id="$1" body="$2"
    validate_path_param "$id" || return

    if ! validate_required_fields "$body" "title"; then
        http_response "400 Bad Request" "application/json" \
            "$(json_error "title is required")"
        return
    fi

    local title body_text published
    title=$(get_json_field "$body" "title")
    body_text=$(get_json_field "$body" "body")
    published=$(get_json_field "$body" "published")

    db_update "posts" \
        "title = $(safe_sql_string "$title"), body = $(safe_sql_string "$body_text"), published = ${published:-0}" \
        "id = $id"

    local changes
    changes=$(db_get_changes)
    if [ "${changes:-0}" -gt 0 ]; then
        http_response "200 OK" "application/json" \
            "$(db_select "posts" "id, title, body, user_id, published, created_at" "id = $id")"
    else
        http_response "404 Not Found" "application/json" "$(json_error "Post not found")"
    fi
}

delete_post() {
    local id="$1"
    validate_path_param "$id" || return
    db_delete "posts" "id = $id"
    local changes
    changes=$(db_get_changes)
    if [ "${changes:-0}" -gt 0 ]; then
        http_response "204 No Content" "application/json" ""
    else
        http_response "404 Not Found" "application/json" "$(json_error "Post not found")"
    fi
}
